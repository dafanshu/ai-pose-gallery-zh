# Harness 迁移实现与验收

## 设计

原站共享业务代码，新增 `src/lib/runtime.ts` 作为运行环境适配层。无运行时标志时仍是原网站；Harness 在服务端加载 HTML 时注入固定路径与能力开关。

- `vite.harness.config.ts`：独立前端产物，插件 `harness/app`，不改变网站 `dist`。
- `harness/client.js`：宿主 ModuleLoader/Cordis client，注册 `conversation.view`，显示构建/数据缺失诊断，承载本地完整工作台。
- `harness/index.mjs` / `server.mjs`：生命周期注册、owner 鉴权、静态资源与模型代理、固定 Comfy HTTP/WS。
- `src/lib/runtime.ts`：路径、命名空间、传输头与持久化敏感字段剔除。
- `src/lib/studioBackup.ts` / `StudioBackupPanel.tsx`：版本化数据迁移、严格 schema、替换确认和导入互斥。
- 原路由/页面、五供应商业务、工作流与 Python 插件都保留，不重写为简化生图表单。

## 已验证

基线全部 86 个源代码测试（原有 75 + 前端新增 11）和后端 14 个及 rc.1 兼容 5 个测试，共 105 通过。测试不会调用真实付费模型。模拟宿主注册不是“宿主已装好”的证据。

单独执行：

```sh
node --import ./scripts/register-test-modules.mjs --test tests/*.test.mjs harness/tests/*.test.mjs
```

## 必须完成的真实环境验收

1. 批准依赖环境中执行 `pnpm run build:harness`、`pnpm run build`、`pnpm run lint`、`pnpm run check:harness-package`。保留原锁文件，先解决供应链审核，不换源/降级/跳过策略。
2. 在官方 0.2.2-rc.1 web profile 加载插件；确认「角色工作台」出现。鉴权失效后 HTTP/WS 应拒绝，重新登录后恢复。未知/旧版本不能静默免鉴权。
3. 图库六个 JSON 数据源、各来源缩略图/原图、多角度、深度切换、搜索筛选、加载失败/重试和版权警示逐项检查；不依靠只含源码的交付包验证图库完整性。
4. 选择脸/衣服/姿势、上传本地图、附加参考、工作流图片槽、随机配方、拼图、对比、放大下载。切换七个页面后配方不丢失。
5. 重复打开/关闭弹窗、取消导入、快速连续点击、切换 Harness 对话/视图、浏览器返回/前进；确认不影响宿主路由、不重复提交、不无声覆盖状态。检查生成中宿主视图被卸载的表现。
6. 每个真实供应商先用已批准的测试账号和最小请求：设置→模型发现→生成→错误→重试→结果→历史快照恢复。供应商/模型权限或收费由操作者自行确认，本次未试发。
7. ComfyUI：连接检测、工作流字段、模型缺失、上传失败、提交、排队、实时进度、WS 中断转轮询、生成完成、刷新恢复、停止跟踪。停止跟踪不能误报取消了后台执行。
8. 备份往返：旧站导出、Harness 导入、先取消再确认，检查上传图片/历史/快照；恶意 schema、超大文件、未知版本不能写入。导入期间生成/恢复/历史操作应被拦截。
9. 检查 localStorage/IndexedDB/下载备份无配置 API Key；刷新后 Key 为空；Host Cookie 和 Host Authorization 不出现在上游。确认主机日志/反向代理不记录 `x-studio-*` 头。
10. 验证单用户、本机或经过 TLS 的可信部署边界。它不是多租户服务器；不暴露无登录公网服务，不把图片 MIT 化，不自动重分发远程素材。

## 已知边界

- 真实 Harness 版本、依赖生产构建、浏览器视觉和真实生图尚未验证。
- 只面向 web profile；Electron file://、ACP/headless 未实现。
- API Key 页面内存、配方/历史浏览器存储，不是 Harness 凭据服务或跨设备同步。
- 未新增聊天生图工具/附件写入桥接，GUI 生成保留原能力。
- 原站最高 30 条新增历史策略保留；备份导入允许较大旧存量但不是无限图库系统。
- 跨窗口同步与宿主 tab 卸载后云端请求持久化未新增；Comfy 继续按已有任务记录恢复。
- 素材与已审核依赖不随本次源码包提供。约 1.19 GB 的素材从完整原仓库目录只读提供。

## 回滚

从 Harness 移除/停用新增 `ai-pose-studio` 插件即可，不改原网站部署。该操作不自动删除独立浏览器数据。回滚源码前先保存未提交改动和导出数据，使用附带补丁的反向检查；不要盲目覆盖文件。
